# X-Native complete product audit

**Date:** 2026-09-16  
**Scope:** current working tree after commits `eb0bb14` through `dfaca1f`  
**Method:** source inspection, action-to-handler tracing, model/serializer inspection, regression-test inspection, static searches, and the repository gate definition. This is a capability audit, not a Figma marketing comparison.

## Executive summary

X-Native is a serious native design editor with a strong rendering and document core. The strongest areas are the GPU renderer, JSON `.x` format, vector editing, auto layout, prototype data model, `.fig` import, SVG/PNG/PDF sinks, comments, components, variables, and MCP integration.

The earlier audit contained several stale findings. The current tree now has:

- Functional navigation rail and Variables creation controls.
- Persisted theme preferences.
- Local `.xlib` library publishing.
- A font browser in the typography inspector.
- Document-level undo checkpoints for text-style edits.
- Component slot creation and descriptions in the inspector.
- Prototype device chrome.
- Automatic local version archives with an Open version menu action.
- PNG and PDF export code and UI.
- Hover, delay, back, drag, key, and other prototype trigger plumbing in the player.

The remaining gaps are mostly strategic or deliberately scoped. The biggest product gaps are collaboration/presence, plugins, a full branch/merge UI, robust version restore/diff, `.fig` export, and a complete component-slot content editor.

## User and feature audit

### Fixed since the earlier audit

- Navigation rail no longer only changes its highlight.
- Variables can be created from the Tokens panel.
- Theme selection persists at `~/.config/x-native/theme`.
- Libraries can be published to `.xlib`.
- Font families can be browsed and selected.
- Text style actions are document-undoable.
- Component slots can be created on master nodes.
- Component descriptions can be edited.
- Prototype device chrome can be toggled.
- Previous `.x` saves are archived under `.x-native-history` and can be opened from File > Open version.
- PNG/PDF export is present in `x-render`, `x-native`, the export jobs, and the editor export panel.

### Still open

1. **Component slot content authoring**: create a slot exists, but an instance needs a clear UI to insert, replace, and clear slot content.
2. **Shared style breadth**: text styles are much further along than color, effect, and layout-guide styles; all style definitions should share one undoable registry workflow.
3. **Full version history UX**: archived versions now open safely as unsaved copies, but there is no timeline, metadata, diff, restore-in-place, or branch-from-version command.
4. **Git branching workflow**: no branch selector, compare view, conflict resolver, or safe merge operation in the app.
5. **`.fig` export**: import exists; writing Figma's proprietary format does not.
6. **Prototype presentation**: device chrome is a lightweight preview frame, not OS/mobile simulation, device settings, offline player, or native mobile viewer.
7. **Font technology**: font browser exists, but CFF/OTF subsetting falls back to whole-font shipping.
8. **Library distribution**: publish is local-file publishing, not team permissions, remote registry, review, or update notification.
9. **Collaboration and plugins**: no production sync/presence/comment cursors or sandboxed plugin runtime.
10. **Sketch fidelity**: Sketch import exists in the format layer, but broad real-world fixture coverage and export parity need more verification.

## Tool and function audit

- **Undo/redo:** page/editor history is mature; document checkpoints now cover style definitions, but every document-level registry mutation should use the same transaction helper.
- **Export:** PNG/PDF implementations are present and should be covered by a user-level smoke test that writes both files and verifies signatures.
- **File safety:** save errors keep the document open; version archive failures do not block saving. The archive uses timestamp names, so two saves in the same second can collide and should eventually use a monotonic suffix.
- **Prototype:** trigger data and player routing are broad. Test delayed navigation and overlay cancellation under fast repeated pointer input.
- **Library:** `.xlib` serialization is deterministic and versioned. Publish currently uses version `1`; incrementing/publishing an existing library needs a dedicated version selection policy.
- **Variables:** generated names are deterministic and unique, but editing/renaming/deleting variables deserves a first-class UI.

## Visual and UX audit

### Strengths

- Native GPU scene pipeline rather than browser canvas.
- Consistent semantic theme roles and WCAG audit command.
- Real tooltips, hover states, keyboard shortcuts, contextual panels, and inspector controls.
- JSON documents remain human-readable and diffable.

### Issues

- The left rail has more concepts than the current content model; Agents is informational rather than a full conversation workspace.
- The component inspector can become vertically dense when variants, properties, slots, export controls, and typography are all visible.
- Device preview chrome is intentionally minimal and does not yet communicate selected device, viewport dimensions, or safe areas.
- Error feedback is primarily a status string; important save/export/import errors should have persistent, actionable notifications.
- Some empty states describe future capabilities rather than offering a next action.
- Platform-native window/chrome behavior remains intentionally cross-platform rather than matching macOS/Windows conventions.

## Developer/code-health audit

### Strengths

- Workspace lint policy denies correctness/suspicious/unsafe/unused-must-use classes.
- `scripts/check.sh` covers formatting, clippy, tests, docs references, CLI smoke, dead-code ceiling, and the NaN ordering regression guard.
- Regression tests are extensive across core/editor/format/render/app behavior.
- The `.x` format is deterministic and suitable for review workflows.

### Issues

- The Rust toolchain is not installed in this execution environment, so the full Cargo gate could not be run here.
- Dependency version drift remains (`ttf-parser`, `tiny-skia`, and platform crate churn).
- Dead-code debt is explicitly ratcheted rather than zero; it is tracked in `docs/KNOWN_DEBT.md`.
- Root-level historical Markdown files still obscure authoritative docs.
- No automated guard checks that every new UI action has a visible affordance and a regression test.
- Local version archive needs collision-safe naming and a manifest with timestamps/user intent.

## First-time-user walkthrough

This was traced as a cold-start user journey rather than a code-only feature list:

1. **Launch:** the non-demo dashboard clearly says `Your design workspace`, shows `New file`, `Import file`, and `New board`, and does not pretend cloud collaboration is available.
2. **Create:** `New file` opens an untitled design document directly; `New board` opens the infinite-canvas document type.
3. **First canvas interaction:** the editor exposes the tool rail, canvas, Layers/Library/Tokens panels, and the inspector. The Variables rail now reaches real token content and creation controls.
4. **Typography:** selecting a text layer exposes a font family field; the field opens a registered-font browser rather than requiring the user to know a hidden font name.
5. **Component workflow:** selecting a master exposes property controls, slot creation, and a description field. Selecting an instance exposes its typed overrides.
6. **Prototype:** Flow preview has Back/Exit controls and a Device toggle; hover/delay/back behavior is represented in the player path.
7. **Save/recovery:** Save creates a normal `.x` file and archives the previous version. File > Open version opens an archive in a new tab, protecting the current file.
8. **Export:** the Export panel exposes PNG/PDF alongside SVG and code-oriented formats.

### First-time-user friction found and repairs

- **Repaired:** the empty dashboard now has direct `Create new file` and `Open existing file` buttons in the empty state, instead of requiring the user to discover the top-bar button or keyboard shortcuts.
- **Repaired:** collaboration is labeled `Team features · Coming later` outside demo mode instead of presenting a confusing invite action.
- **Repaired:** first launch now shows a one-time welcome guide with Design, Prototype, and Ship steps, plus Open sample project, Start with blank file, and Skip actions. Completion is persisted in `~/.config/x-native/onboarding-complete`.
- The inspector has many dense controls; progressive disclosure for advanced component/prototype controls would reduce first-session overload.
- Opening an archived version in a new tab is safe, but the UI does not yet show version timestamps, previews, or a restore/branch action.
- The Agent rail is an integration status surface, not yet a conversational agent workspace.

These remaining items are UX/product gaps, not silent failures.
